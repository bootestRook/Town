# 钻石快捷购买表面约定

范围为Godot 4.7.1中文竖屏本地Demo的钻石快捷购买页，模式为Operate。用户提供的商人截图和可追溯原资产是视觉依据，沿用主界面手绘奇幻材料与源字体；白色微信容器不进入游戏。

THESIS：玩家看清六档钻石及每档首充奖励，点击完成一次客户端模拟结算，观看奖励后继续购买或回到原页面。
OWN-WORLD：源红发商人横幅、青黑底、六种品质卡框、钻石插画、首充斜角标、CNY价格与「钻石充值」底栏构成页面。源卡框自带价格槽，只保留单层，价格文字置于实际槽内中央。
STORY：顶部实际余额 → 商人横幅 → 三列两行六档 → 点击购买 → 已结算奖励入场/爆光/循环 → 该档首充标记移除 → 返回原英雄或招募上下文。
FIRST VIEWPORT：720宽源舞台随视口宽等比缩放，高度随视口延展，覆盖750×1334、360×640、750×1624。六卡224×350起步、列距10、行距5；长屏扩展横幅可见区与卡底，图标和字号不单独放大；固定底栏及右侧返回避开卡片。
FORM：固定 `.tscn` 保存六卡、顶栏、底栏、帮助与奖励覆盖层。仅钻石页签，不实现每日特惠、英雄礼包、道具礼包页签。旧通用商城列表及购买确认路径删除；礼包领域逻辑保留但不新增UI入口。帮助明确客户端模拟不产生真实扣款。

六档基础数量为60/300/980/1980/3280/6480，价格为CNY 6/30/98/198/328/648；每档首次额外同额，复购只有基础数量。购买意图使用快照下一订单号，领域原子记账并返回不可变回执；表现层不发奖。首充状态与订单只存在本次运行，不新增服务器、支付SDK或磁盘保存。规则由 [ADR0012](../../docs/adr/0012-client-diamond-recharge.md) 持有。

卡片按压0.09秒缩至0.96并恢复。奖励以78%黑遮罩阻断下层，源 `js_welcome` 80帧约2.6667秒入场接 `js_welcome_XH` 64帧10.6秒循环，16帧爆光按30 Hz播放；物品0.333秒出现并弹至1.05倍，标题依源缩放关键点，余额从0.333秒起滚动0.65秒。播放源45号点击及49号获奖音效并遵循声音设置；46号次级音效已导入但此页未播放。0.35秒内禁止关闭回执以防穿透，此后关闭只结束表现，不再结算。

返回恢复被快捷页暂时隐藏的英雄/招募分页、滚动和弹窗节点。三尺寸原生输入覆盖六档、首充/复购、连点、动效推进、静音、金币入口与英雄/招募返回，共18张捕获，见 `.impeccable/review/diamond-shop/` 和 `validation/diamond_capture.log`。主界面24张与宠物/神器12张原生回归通过。独立终审 `resolved / remaining: clear / disposition: ship` 仅覆盖此前价格槽单层及文字居中修正，见 审查记录（本机验收记录，未随工程归档），不扩大为整页所有质量维度、整款游戏、移动真机或导出包验收。

来源、采样参数、验证日志与边界见 [钻石充值页记录](../../docs/research/DIAMOND_SHOP_UI_2026-09-30.md)。其他表面的既有约定保持不变。
