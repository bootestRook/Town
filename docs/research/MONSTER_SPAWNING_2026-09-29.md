# 野外怪物数量、出生与巡逻核查

2026-09-29。针对用户截图中怪物数量过多、排列整齐的问题，先核对源代码、配置及地图 prefab；在后续“人物穿模建筑，也需要处理”请求中一并落实下述修正。

## 修正前 Demo 的原因

原 `src/features/town/domain/town_combat.gd` 按 `max(3, ceil(state.heroes.size()/3))` 创建每种怪物。48 名地图英雄导致疾风狼、棕熊各 16 只，共 32 只，取的是拥有数量，未使用出战数量。该逻辑是此前扩充英雄时加入的 Demo 适配，不是源项目刷怪公式，现已删除。

出生位置按 280×240 世界单位的规则网格排列，再吸附到最近可行走格。空闲怪物只会返回固定 `spawn`，不巡逻；复活也回到同一位置。因此降低数量可以改善密度，但还必须修正出生点和空闲行为才能消除队列感。

## 源项目实际调用链

源地址见 本机来源索引（未随包提供；[资源来源登记](../../THIRD_PARTY.md)），以下均为源拆解目录内的相对路径。

1. `02_代码模块/FieldMapModel.js:66–72,111–116`：地图档位默认 1，之后由服务器地图进度/切换结果更新；不按拥有英雄总数计算数量。
2. `CptMapField.js:74–80`：读取地图档位，并通过 `readMapSXD()` 将预制体点列表传给战斗地图。
3. `btCfgHelper.js:170–180`：三个野外分别读取 `c6_map_1/2/3` 和 `c6_sxd_1/2/3`。本调用链不采用另存的 `c8_map_1.num_max`。
4. `btMapField.js:162–209`：解析 `gw_pt` 的怪物 ID 与数量，逐种初始化；`sxd_pt` 提供可选出生点编号。
5. `btMapField.js:142–160,211–250`：从候选点中随机选点，读取 prefab 的实际坐标，再转成菱形格中心创建角色。

## 空闲、战斗和补充

- `AIStateConfig.js` 的 `FieldMonsterAIFSMConfig` 启动进入 `RANGE_PATROL`；发现目标后追击、进入射程攻击，失去目标返回巡逻。
- `btMonsterField.js:40–48` 使用传入 `patrolRange`；其实际来源是 `c2_guaiwu.search_range`，狼、熊均为 300。该值控制出生点周围的巡逻范围和索敌范围，不应误用 `c6_sxd_1.r=100`。
- `btMapBase.js:199–231` 在出生点周围筛选可通行、半径内的格偏移作为巡逻目标；`AIStateRangePatrol.js` 按格移动，到达后随机停留 **2,500–5,000 毫秒**，停留时仍检查敌人。
- `btMapField.js:317–356` 在普通怪移除时记录 `tick.time + frequency`，到期调用 `createMonster`，重新选择出生点；不是将原对象永久复活在同一 `spawn`。`btTick.js` 的 `time` 使用秒，巡逻状态中的 `dtMS` 使用毫秒。
- 源文件的出生点占用计数存在可疑实现：`addSXDUse` 首次写 0、`subSXDUse` 却加 1；巡逻候选是成对保存的偏移，但取值索引也值得复核。这些是本包代码事实，不能直接宣称原版严格保证无重叠。后续实现需要明确保留规则和修复计数的差别，不照搬疑似错误。

## 已落实范围

1. 当前 Demo 以第一野外第一档为基线，普通怪恢复为 3 狼＋3 熊，取消按拥有英雄人数扩容。
2. 导入上述原出生点及关卡引用，取消规则网格摆放；正常初始化和补充均随机选点，并正确维护占用。
3. 接入出生点周围 300 范围巡逻、2.5–5 秒停留以及原索敌/攻击/失去目标后的转换。
4. 使用 10 秒补充队列并重新抽点；验证 48 名已拥有、3–5 名出战时数量不变，长时间击杀后持续补充，巡逻不出界、不进入建筑或堵塞出口。

本轮结论来自当前本机 APK 拆解文件，不代表线上热更新后所有版本或任意玩家档位；未对原游戏进行实时录像或服务器状态采样。

导入器 `tools/import_field_reference.py` 从当前 `c6_map_1` id=1、`c2_guaiwu` 和 `Map.json` 提取数量、频率、范围和实际出生格；由 `import_navigation_reference.py` 接入既有重建链。来源哈希和坐标转换记录在 `art_source/heroes/field_sources.json`，运行时读取 `town_monsters` 和 `town_monster_spawns` 表。

`TownMonsterPopulation` 负责活体出生点占用、随机补充、巡逻和停留，使用独立 `town.field` 随机流。出生时排除被其他活体占据的位置，无空位延后补充；重复死亡不会增加总数。巡逻目标和沿途格都限制在野外，常态巡逻路线不越过出生点半径；接敌后允许在野外追击，再返回巡逻。源包可疑的占用计数与偏移索引错误没有照搬。

验证脚本：`tests/test_town_monster_population.gd` 覆盖人数独立性、种类数量、随机复现、两分钟巡逻/停留、16 次死亡/补充、接敌/撤下后恢复、无效出生数据；原生截图为 `validation/world_navigation/field_initial.png` 与 `field_patrol.png`。完整检查结果与城镇修正共用 `validation/world_navigation/project_check.log`。
