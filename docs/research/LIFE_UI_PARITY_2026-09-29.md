# 医院、餐馆、旅馆、酒馆界面复刻

日期：2026-09-29。目标为用户提供的四张截图及本机原 APK 的生活建筑页面。截图顶部微信容器栏属于宿主，不进入 Godot 游戏界面。

## 依据与实现

查询入口仍为 本机来源索引（未随包提供；[资源来源登记](../../THIRD_PARTY.md)）。源 `BuildLifePnl.json`、`BuySeatPnl.json`、`DealInDailyReportPnl.json` 与 `BuildLifePnlCtrl.js`、`BuySeatPnlCtrl.js`、`DealInDailyReportPnlCtrl.js` 分别提供固定结构和调用链。使用原字体、室内、机器、幕布、货架、徽章、图标、进度纹理与弹窗边框，新增资源 UUID 和 SHA-256 登记在 `art_source/life_ui/provenance.json`。

- 固定结构：`scenes/town/life_page.tscn`、`service_seat.tscn`；离线编排入口 `tools/author_life_page.py`。原 `author_building_scenes.py` 已删除旧生活店和席位布局，统一调用新入口。
- 源资源及配置补全：`python tools/import_life_ui_reference.py`，随后 `python tools/project.py data` 和 `python tools/project.py assets`。原建筑导入入口也执行补全，避免重新导入后丢失字段。
- 表现：`life_page.gd` 读取快照、提交升级/生产/席位购买意图，不直接修改经营状态。`life_format.gd` 保留百分比小数和货币缩写。
- 规则：`TownOperations` 保持状态所有权；`town_life_rules.gd` 计算阶段信息、检查席位购买及服务付款，并记录分店日报。操作均经所属 Feature 公开接口提交。

原图内容按项目 750×1334 逻辑画布布置，小屏等比缩放，长屏居中留边。机器在幕布之后绘制；透明恢复图中的原始留白不当作可见内容。人物读取现有真实英雄头像，按 alpha 有效区域生成 AtlasTexture，在柜台处裁为服务肖像。

## 信息及操作

| 操作/信息 | 当前行为 |
| --- | --- |
| 标题、等级、加价、减时、人数 | 显示当前领域数据；原版 `Lv`、`S` 计量标记按参考保留 |
| 升级进度 | 读取 `c36_jz_*` 的 `jd_type` 阶段标记；不再假定每五级一段 |
| 下一阶段奖励 | 分别显示原售价、沙漏或人数图标与增减值 |
| 成品说明 | 有货时进入默认展示，点击成品显示；外部点击关闭；恢复、售价乘数、时间减项实时刷新 |
| 成品售罄 | 隐藏成品、数量、价格及旧说明，显示源文案“没有商品了,请尽快制作！”；生产后恢复 |
| 原料拖拽 | 拖入操作台后按源配方一次生产全部可用材料；外部释放/失焦/关闭取消拖拽；不会重复扣费 |
| 原料不足 | 禁止空拖拽，显示原白色“获得途径”气泡；来源面板显示原料、源描述、交易所收购、怪物掉落及锁定的挂机奖励入口 |
| 来源跳转 | 交易所直接定位对应原料预购，提交后进入真实订单；怪物掉落返回当前地图；挂机领奖尚未接入，保持锁定 |
| 建筑说明 | 显示原建筑说明标题、源用途描述、“当前总加成”、价格增加和时间减少两张信息卡 |
| 英雄服务 | 消耗一个真实成品并付费，占用真实席位，倒计时结束恢复对应需求；关闭页面不停止领域运行 |
| 钻石席位 | 使用 `c36_price` 的 `limit_price_2/3`；余额不足及重复购买不扣费，购买后增加真实可用容量 |
| 等级席位 | 展示第一个增加至两人的源等级门槛；与额外购买的席位相加 |
| 日报 | 独立统计当前店的实际销售金额、时间、英雄、商品；本地日历到零点清零；空白处关闭 |
| 返回 | 回到地图；弹窗出现时隐藏外层返回及日报按钮，避免穿透 |

四张参考状态对应数值：医院 Lv30 为 79%、1432、10 秒；餐馆 Lv30 为 170%、2700、10 秒；旅馆 Lv28 为 238%、4056、11 秒，进度 80%；酒馆 Lv29 为 146.5%、2218、11 秒，进度 90%。售价按源代码向下取整，酒馆不再错误四舍五入到 2219。

## 验证与明确边界

`tests/test_life_ui_runner.gd` 独立运行经营规则用例，185 项断言通过；包括源截图数值、真实阶段区间、席位购买的原子性、分店流水和跨日清零。`tests/capture_life_ui.gd` 通过 86 项引擎鼠标检查验证入口、取消拖拽、生产、说明浮层、升级、席位购买、日报、售罄、缺料来源跳转、真实预购与返回，并捕获 750×1334、360×640、750×1624。日志和图片在 `validation/life_ui/`。

`reference_1.png` 至 `reference_4.png` 使用测试内专用参考存量，不能当作游戏初始化状态或原版存档。正常启动仍使用现有 Demo 五级建筑、有限资金和材料；新增钻石初始 1155 是测试资金。顾客是当前原型的艾比、特伦斯、芭芭拉，不强制替换为参考截图里的访客。

当前仍有明确边界，不能宣称完整原游戏 1:1：金币补充/钻石商城及月卡购买依赖尚未接入的外围系统，入口提供不可用反馈，不伪造充值或权益；挂机奖励系统未接入；生活店仍沿用既有 1–40 级与一阶产品范围（源等级表为 300 级）；无跨进程存档。机器使用已有 8 帧离线序列，未据此宣称原骨骼动画逐帧一致。真实触屏设备未验证。

最后一次 `python tools/project.py check` 已通过：22 个 Python 测试、769 个 Godot 断言、数据/资产/交付/架构检查、发布源指纹及运行冒烟均通过，退出码为 0，无 `SCRIPT ERROR` 或 `ERROR`。完整 UTF-8 日志见 `validation/life_ui/project_check.log`。独立 UI 审查提出的售罄、缺料及建筑说明问题均已修复并复验。

同目录并行新增主城模块期间，首次全项目检查曾被数据 ID、类型推断及数字字典键问题阻断。本轮仅对 `town_recruitment.gd` 和 `town_hero_management.gd` 作必要的 Array 显式类型及价格字典整数键修正，未覆盖其他主城实现。最终记录以上述完整通过日志为准。
