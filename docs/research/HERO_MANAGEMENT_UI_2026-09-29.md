# 英雄上阵、培养与图鉴三页记录

日期：2026-09-29。状态：本地三页已实装，原生回归已通过。用户提供四张新参考，要求英雄信息页的「更换英雄」进入完整上阵、培养、图鉴三页。本记录对应此次页面、返回路径与队伍语义变化，区分已实现行为和源版本差异。架构决策见 [ADR 0010](../adr/0010-hero-management-pages.md)。

## 范围与现有页面关系

英雄信息页「更换英雄」与半屏列表「修改阵容」进入三页管理界面的上阵页，招募「图鉴」进入同一界面的图鉴页。更换英雄先关闭原详情，不再只提供序列选择弹窗；管理页返回原抽屉或招募入口，不回到刚关闭的详情。从培养卡进入独立英雄详情时则保留管理页上下文，详情返回恢复培养tab及原滚动位置。当前详情英雄在进行中的远征队伍时，「更换英雄」入口先拒绝跳转，符合源 `CptHeroInfoItem` 的相关限制。

现有私有背包、装备详情、原Spine待机、宠物与神器操作保留。固定结构继续使用原生Godot `.tscn`，沿用720源宽和750×1334项目画布，适配360×640及750×1624；底部上阵、培养、图鉴与返回箭头固定，三页内容分别滚动，管理全屏打开时阻断下层地图输入。

此次视觉依据为新四图。培养8入口、图鉴4分类按新参考组织；源APK中同名模块的结构并不完全相同。不可因界面存在锁态入口，就将对应养成系统记为已实现，也不得用源旧结构替代用户已经明确要求的新页面。

| `main.expedition_team` / `expedition_team` | 新增独立五人远征名单及命令；原地下城队伍弹窗改读写此状态，守卫与海底遗迹也读取独立远征名单。远征战斗读取这份名单。 |
| `main.camp_level` | 本地演示初始5级，与本项目既有主城及生活店演示初值一致；不冒称源新账号初始等级。 |

## 已实装的上阵页

上部在源营地场景中保留15个台位，以实际容量决定开放、加号或锁定，当前初始人数3/7；已上阵英雄播放既有原待机。下部用四列165×202卡呈现已拥有英雄，按战力降序、同战力ID顺序排列，已上阵卡显示遮罩与勾选；全部/火/水/风/光过滤只改变显示。全部按钮使用参考 `ALL` 标签，紫色圆底与快捷上阵胶囊为固定场景样式绘制，不冒称源切图。锁位与下一营地等级提示不代表本轮新增营地升级系统。

单卡及上部台位提交 `hero_team`，快捷按钮提交 `hero_quick_deploy`。`TownHeroDeployment` 使用同一快照校验单人资格、容量和远征状态；快捷选择先保留不可撤下的进行中远征成员，再从当前元素、已存在地图实体的候选中按战力降序、同战力ID顺序补满，统一提交。被保留的远征成员占用容量，可与当前元素不同。无候选或无效元素时保持原名单；领域提交后实际地图 `deployed` 状态同步，不只更新卡片勾选。

撤下后可立即重新上阵；单卡与快捷操作共享无等待规则，不再记录冷却时间或显示更换冷却提示。进行中的远征成员不得通过地图单切或快捷操作绕过限制。已经付费的生活服务、复活和地图返城沿用当前真实规则，不因换页、动画或按钮反馈立即结算、瞬移或补血。

未烘焙地图动作的招募待命英雄不具备地图上阵资格，不能使用其他英雄的角色或空壳实体冒充；当前剩余26种未烘焙地图动作的英雄在实际招募后仍可待命、培养和进入独立远征，不能地图上阵；不自动把26种定义变成已拥有英雄。页面能列出或查看一个英雄，不等于该英雄已接入地图动作。

## 已实装的培养页

按新参考保留两行共8个入口，当前仅「升星」可用，其余7个使用锁图且点击只反馈未解锁；不为遮挡名称编造文字。下方每行含原待机英雄卡、四个源技能/等级、灵魂石现有量/需求量与升星按钮；可升星且材料足够的英雄优先，其余按战力/ID排序，满星显示对应状态。

培养行的「已上阵」标记采用源图 `d042ecd6-ce17-4e0f-a5aa-4817ff6acf84`，替换此前临时文字菱形。升星提交已有 `hero_star` 命令，材料充足时真实扣料并更新星级、技能和属性；不足时打开该英雄灵魂石获得途径，点击技能打开实际技能说明。卡片按当前列表序列进入详情，返回培养时保留tab和滚动，页面切换本身不改变实例。

英雄详情中已有宠物、神器页及其仓库、装备和养成功能继续可用；管理页的锁态只描述本次新参考入口，不反向关闭旧路径。当前APK培养控制器只有3类，故这里是按用户新参考组织的本地页面，不是源8类完整养成子系统移植。

## 已实装的图鉴页

展示数据与拥有实例严格分开：按 `tujian.show_id` 取最高阶静态定义，包括其品质、星级和技能展示依据；不修改实际英雄等级、星级、灵魂石、装备或拥有状态。静态图鉴详情不得接收拥有英雄的养成命令，也不能为了展示最高阶而临时改写一个真实英雄后再恢复。

四列卡片沿用源品质、职业、元素和星级图，播放既有原待机；已拥有优先，再按品质降序与源图鉴rank排序，未拥有卡调暗。图鉴点击打开最高阶只读属性及技能说明，没有养成按钮，不使用真实拥有英雄详情承载临时最高阶状态。四分类边界如下：

| 分类 | 数据约定 |
| --- | --- |
| 全部 | 展示本项目已导入且有对应展示定义的英雄，不等于已拥有，也不因源表总行数而伪造缺失条目。 |
| 卡池 | 依据当前招募等级可抽取品质及正 `weight` 筛选，与实际招募规则一致，不把所有图鉴英雄均视为当前可抽取。 |
| 特殊卡池 | 当前版本缺少直接成员配置，保留空列表，不用高品质、名称或外观猜成员。 |
| 活动 | 当前版本缺少直接成员配置，保留空列表，不把 `event_id` 等存在字段自动解释为新图对应的完整分类规则。 |

空分类说明的是现有版本资料缺口，不宣称原游戏没有特殊卡池或活动英雄。源APK图鉴控制器仅有全列表；新4分类壳、当前招募筛选和最高阶只读展示应分别验收，不能合并称作全量原图鉴机制已实现。
