# ADR 0007：主界面与本地 Demo 子系统

日期：2026-09-29。用户要求还原截图红框主界面，不加入活动图标；随后明确包含二级页面及子系统，并确认“demo实现改成前端就行”。

主界面保持源顶栏、五项底栏、同项关闭、异项切换、顶栏入口关闭底栏选择。所有可变数据仍由 TownOperations 持有；招募、英雄成长、资源补充与独立远征用 town 内部领域协作者处理。Presentation 只发送 Intent、读取快照。固定页面和动态项模板保存在 tscn。

不新增 Autoload、依赖、跨 Feature 调用或存档格式。仍为会话内离线 Demo；关闭进程后重置。静态数据通过现有 CSV/schema 管线导入，源资源及 SHA-256 可追溯。

本地与原版的边界：APK 只有服务器请求和响应处理，没有招募服务端随机算法、完整战斗结算、订单和榜单服务。Demo 使用注入的 town.recruit 随机流、源英雄池和品质权重；战斗使用独立副本、源伤害公式和已接入的技能规则；支付、广告在弹窗明确以模拟动作触发，不产生真实订单。不能将此视为原服务器等价实现。玩法子模式的本地战斗复用同一远征引擎，其数值与内容范围须在交付记录中逐项说明。

主地图英雄名单由当前常驻英雄配置提供，不在主界面里固化数量。同一工作区另一任务已扩充至 48 名常驻英雄；新招募英雄进入待命名单、可参与远征队伍，没有烘焙全套动作前不伪装成已完成所有英雄的地图形象。

独立远征读取各模式自己的敌人属性和关卡组合，技能协作者读取主动伤害/治疗的源倍率和冷却。英雄进阶读取源天赋后继节点；常驻英雄通过自身领域状态更新属性，待命英雄独立计算快照。海底遗迹使用独立体力与计时协作者，不伪装成地下城；当前只实现本地打捞。具体未完成的源子系统和本地替代规则必须保留在 `docs/research/MAIN_UI_2026-09-29.md`，不因采用源资源与通过测试而扩大完成声明。

验证：资源真值同步、同项关闭和跨页返回、无穿透点击、原配置读取、资源不足不扣款、重复领奖幂等、确定性招募、战斗胜负与退出、正常/窄屏/长屏，并执行 project.py check。

补充：宠物、神器、道具使用和常驻商城分类沿用同一领域状态所有者与 CSV 管线；使用独立注入的 `town.collections` 随机流，避免开蛋或开箱改变招募序列。所有新对象从源道具或玩法奖励取得，不自动赠送整套收藏。宠物升级/升星、神器升级/重置/分解按源配置扣费和返还；商城 CNY 价格来自 `c70_product_list`，付费仍须显式模拟确认。此扩展不改变存档格式，不新增跨 Feature 依赖。

远征战斗补充 `town.expedition` 流，用于源命中、暴击、伤害浮动、Buff 概率及精灵蛋奖励。来源为 btPropertyComputer、btHeroAttack、btPassiveSkill 与 btBuff 的注册规则；已替换先前仅三属性的简化伤害。宠物读取装备快照及 btPet 触发规则；首领先验证门槛、队伍和材料再扣费；领奖只执行一次掉落。保持副本状态与小镇野外生命周期隔离，空间走位与技能动画仍单独记录为未完成项。
